# 새로고침 로그인 유지

최신 develop 6a4c8a0(2026-11-24 17:24 KST)의 session.js / live-store.js / main.js를 확인했으며, 메모리 인증만 있고 복원 처리는 없었습니다.

변경 동작:
- 같은 탭의 새로고침을 위해 sessionStorage에 토큰·만료 시각만 보관합니다. 역할·소속·개인정보·업무 입력 내용은 저장하지 않습니다.
- 최초 라우터 생성 전에 GET /api/v1/me로 서버 세션을 확인합니다. 서버가 반환한 사용자·역할·조직을 두 스토어에 반영합니다.
- 로그아웃 또는 401/403이면 저장 정보를 제거합니다. 서버 연결 실패·5xx는 로그인 정보의 폐기로 취급하지 않고 재시도를 위해 보관합니다.
- 검증 전에는 사용자 정보를 복원하지 않습니다. 동시에 로그아웃하거나 다른 계정으로 바꾸면 오래된 응답이 로그인 상태를 되살릴 수 없습니다.
- 저장소가 차단된 브라우저에서는 메모리 로그인과 경고를 제공합니다.
- 월간 현황은 새로고침 진입에도 다시 조회합니다. 계산기/작업공간의 업무 선택 문맥을 잃으면 월간 현황으로 이동합니다.

범위와 한계:
- 현재 서비스 진입점인 src/prototype/main.js와 공유 세션 스토어를 수정했습니다. 서버 API·DB·로그인 TTL은 변경하지 않았습니다.
- sessionStorage이므로 같은 출처·탭을 기준으로 합니다. localhost와 127.0.0.1은 서로 다른 출처입니다.
- 서버 세션 저장소가 메모리이므로 백엔드 재시작·세션 만료·로그아웃 후에는 재인증이 필요합니다.
- 업무 작성 내용과 계산 결과/선택 항목을 브라우저 저장소에 영구 보관하는 기능은 포함하지 않습니다.
- 이전 앱의 src/main.js는 현 진입점이 아니므로 별도 수정하지 않았습니다.

- node --test src/prototype/*.test.js src/lib/*.test.js scripts/*.test.js : 58개 통과
- npm run build : 통과
