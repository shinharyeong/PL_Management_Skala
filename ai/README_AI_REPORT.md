# AI 보고서 만들기 (ai_report 브랜치)

PDF/PNG/JPG 보고서 한 장을 올리면 구성을 읽어 **보고서 틀**로 만들고, 조회 DB 값으로 채워 편집·내보내기까지 하는 **개발용 데모**입니다.
이 브랜치는 `ai/` 폴더만 바꿨습니다(다른 폴더는 develop 그대로). 서버 저장 API는 없고, 틀은 브라우저 localStorage에만 저장합니다.

## 원칙
- 숫자는 **항상 코드가 DB에서 계산**합니다. AI는 (1) PDF 구성 읽기 (2) 보고 문장 (3) 채팅 요청 해석만 합니다. 칸 숫자는 직접 입력할 수 없고, 계산할 수 없으면 "데이터 없음"입니다.
- 키가 없거나 하루 호출 한도를 넘거나 네트워크가 끊기면 규칙 추출·기본 문구로 대체하고 이유를 화면에 표시합니다.
- 연도·월·조직 수·조직 이름·폴더 이름을 코드에 박지 않았습니다.

## 켜는 법
```
cd ai
AI_PDF_DEV=1 AI_VLM_MODEL=gpt-4o AI_TIMEOUT_SECONDS=120 AI_DAILY_CALL_LIMIT=1000000 \
  python3.11 -m uvicorn app.main:app --port 8000
```
- 화면: `ai/demo/ai_report_studio.html`을 브라우저로 열기(서버 주소 기본 `http://127.0.0.1:8000`).
- `.env` 항목 이름: `OPENAI_API_KEY`(필수), 선택 `AI_VLM_MODEL`, `AI_TIMEOUT_SECONDS`, `AI_DAILY_CALL_LIMIT`.
- 엔드포인트는 `AI_PDF_DEV=1`일 때만 열립니다(`/v1/dev/...`, 아니면 404).
- 데이터 묶음 만들기: `app.chat.datasets.build("set17", <폴더>)` → `ai/.cache/chat/sets/`. 데모 상단 "데이터 묶음"에서 전환합니다.
- 테스트: `cd ai && python -m pytest tests -q` (실제 폴더 대조까지: `AI_DATASET_DIR=<데이터 폴더>`).

## 5단계 흐름
1. **시작**: PDF/PNG/JPG 업로드 또는 틀 아카이브에서 불러오기(불러오면 2단계 건너뜀)
2. **구성 확인**: VLM(그림 읽기)이 주역. 블록 종류(제목·문장·표·계층 목록·차트·각주·숫자 카드), 계층, 합친 표 머리칸, 각주 연결, 날짜 의미를 JSON으로 읽고 코드가 PDF 글자와 대조·보정. 노란 블록은 오른쪽 "이 블록 고치기"에서 처리.
3. **데이터 선택**: 기준 월(기본 최근 확정 master), 블록별 기간, 범위, 비교 기준, 상태(확정/잠정/일부 없음/데이터 없음)
4. **소명 분류**: 수락된 소명 카드를 분류함(1·3·4·5)에 끌어 넣기, 2=3+4 자동, 합계 = Gap 합계 검증, 검토 중은 "사유 확인 중"
5. **보고서(콘텐츠 스튜디오)**: 문서형 블록 편집(끌기·크기·나란히·+ 추가·× 빼기/되돌리기), 글자 직접 수정(숫자 조각 잠금), 서식 바, 표 행·열·단위, 차트(막대/선/도넛/워터폴), 숫자 카드, AI 채팅(미리보기 → 넣기/취소), 실제 OpenAI 보고 문장, PNG/PDF 내보내기, 틀 저장·아카이브

## 검증 결과 (브라우저 직접 조작, 헤드리스 Chrome)
- 두 샘플 PDF 1→5단계 완주(VLM·규칙 각각), 콘솔 오류 없음. 17개 기준 5단계 값 매출 537.8 / 영업비용 509.7 / 영업이익 28.1억(샘플 PDF 표기와 일치).
- 됨: 블록 끌기, 크기 조절, 나란히, + 추가, × 빼기·되돌리기, 글자 직접 수정, 숫자 직접 입력 막힘, 서식 바 전 항목, 표 행·열 추가/삭제/순서, 단위 변경, 차트 4종·지표·N·범위, 숫자 카드, 채팅 미리보기→넣기/취소, 숫자 변경 거절, 없는 지표 "데이터 없음", 블록 PNG·전체 PNG·PDF, 틀 저장·아카이브(이름 변경·삭제)·새로고침 유지·불러오기→3단계.
- VLM vs 규칙(정답 블록은 PDF를 눈으로 보고 정함): 전사 보고 규칙 12/13·VLM 11/13, 경영브리핑 규칙 4/11·VLM 8/11. 글자 PDF는 규칙이 낫고 차트·카드가 있는 그래픽 PDF는 VLM이 낫습니다.

## 추가로 고친 것 (2차)
- 채팅: Gap 건수·종류별, 조직별 Gap 건수, 소명 건수, 비용 상위 항목, 월별 추이 질문 추가(코드가 DB 로 계산). 주별·일별 등 월보다 작은 단위는 “데이터 없음”, “우리 사업부”·지표 없는 비교는 되묻기.
- 5단계: 채울 수 없는 블록에 ⓘ(이유) 표시, 2·3단계에도 ⓘ 도움말. 소명 원문이 두 번 이어 붙던 것 한 번만 표시.
- ‘원인 한 줄 요약’ 버튼(AI 호출 1회): AI 는 줄이기만 하고 숫자·코드는 코드가 원문과 대조해 통과한 줄만 바꿈, 원문은 ⓘ 로 확인.
- 2단계 글자 대조: 글자 PDF 일 때 단어 단위로 오독을 고치고(월정액↔원정액), 못 고친 단어는 노란 표시에 단어를 적음.

- **쓰지 않는 코드(남겨 둠):** `app/pdf_structure/row_guess.py`, `block_guess.py`와 API `/report-data/guess`, `/report-data/guess-block`은 AI 추측 기능용인데 **현재 화면에서는 쓰지 않습니다**(2단계에서 AI 추측을 뺐음). 나중을 위해 코드만 남겼습니다.

## 3차: 박스·표·값 채우기 보완
- **줄 번호 방식(2단계 박스)**: VLM 은 좌표를 주지 않고 "어느 줄 번호들이 이 블록인가"만 답한다(`vlm.py` `build_blocks`, 프롬프트 `pdf-vlm-v5`). 박스는 코드가 그 줄들의 pdfplumber 좌표 합집합으로 만든다. 줄이 빠지거나 겹치거나 떨어져 있으면 노란 표시(`vlm_missed`·`kind_ambiguous`), 글자 줄이 없으면 `box_unresolved`. VLM 이 무시해도 되는 줄은 쪽 번호·숫자뿐인 줄만.
- **칸 쪼개기(`extract.py` `_split_columns`)**: 같은 높이에 나란한 카드·제목·표/차트·다단 본문을 세로 빈 띠로 조각내 읽는 순서(칸별)로 번호를 붙인다. 띠 폭·문장 폭·사각형 경계 등 기하 규칙이며 임계값은 샘플 약 18개로 정함(줄바꿈이 있는 2열 표 등은 오탐 가능).
- **병합 머리 표(`table_header.py`)**: `header_spans` 로 머리 격자를 만들고 열 경로(예: 매출>계획)에서 종류·지표를 읽는다. 열 지표 우선, 소계·합계는 사업부 행 합, 라벨 열이 첫 열이 아닌 표(구분|조직)도 채움. 병합 범위를 모르면 추측하지 않고 `header_ambiguous` + "데이터 없음".
- **값 채우기 정리**: 차트 지표를 제목·범례·축 글자에서 찾고 못 찾으면 "데이터 없음"(기본값 영업이익 제거), 월 축이면 그 월의 추이. `2026.11` 같은 연.월·전체 날짜는 날짜로 유지(기준 월에 맞춰 변경). `{수치}` 가 화면에 새지 않게 `[값]` 으로.
- **화면**: 병합 머리를 colspan/rowspan 으로 그림, `.page{flex:none}`(박스가 줄어든 높이 기준으로 밀리던 버그).
- **개발용 도구**: `python tools/render_boxes.py 파일.pdf [--ai]` (박스 PNG), `python tools/eval_golden.py [--ai] [--fill] [--no-split] -v` (정답 `tests/golden/*.json` 채점: ① 블록 일치 ② 섞임 ④ 값 일치 ⑤ 추측 채움). ③ 숫자 의미 정확도는 슬롯 모델이 없어 측정하지 않음. 서비스 코드에서 import 하지 않음.

## 안 된 것 · 한계 (그대로 적습니다)
- 모델이 같은 단어를 완전히 다르게 읽으면(예: 회선→최신, 외주비→우회비) 자동으로 못 고치고 노란 표시만 함. 목록의 하위 항목이 상위 항목 글자에 합쳐져 읽히는 경우도 있음(호출마다 다름).
- 2단계 "이 블록 고치기"에 **범위(조직) 고르기**는 없음(종류·지표 입력만).
- 원본 PDF에서 읽은 표의 행·열 편집은 직접 눌러 확인하지 않음(추가한 표와 같은 코드).
- 합쳐진 머리칸은 3차에서 `header_spans` 로 읽도록 보완함(VLM 이 병합을 안 알려 주면 `header_ambiguous`). 각주 연결은 모델과 위치 추측이 달라 노란색으로 남음. gpt-4o-mini는 글자 오독·JSON 깨짐이 있어 VLM 전용 모델 설정을 둠. 모델 출력은 호출마다 조금 달라질 수 있음.
- 4단계는 3단계 Gap 분해 블록이 말하는 **비교 기준(계획/직전)** 묶음을 먼저 고르고 다른 묶음에는 “3단계 조건과 다름”을 표시함. **조직 범위로 거르는 기능은 없음**. 서버의 표 ‘주요 원인’ 칸·소명 목록은 건수가 가장 많은 묶음을 쓰므로 4단계에서 다른 묶음을 골랐을 때는 어긋날 수 있음.
- 직전 월 대비 값이 샘플 PDF와 약간 다름(매출 +33.4 vs 33.7, 영업이익 △122.3 vs △122.0). 직전 월을 10월 승인본에서 가져오기 때문일 수 있음(추측).
- 17개 폴더를 데모 "데이터 올리기"로 올리는 경로는 이번에 재확인하지 않음(적재는 `datasets.build`로 확인).
- 전체 PDF 내보내기를 JPEG로 바꾼 뒤에는 다시 돌려 보지 않음. 틀 썸네일은 숫자 없는 뼈대 그림.
- 5단계 문장 수정: 숫자 조각만 잠그고, 지운 숫자 자리는 코드가 다시 채움.
- 브라우저 자동 검증에서 끌기는 가짜 DragEvent, 크기 조절은 마우스 이벤트로 확인함(사람 손 조작과 다를 수 있음).
- `ai/demo/ai_report_studio.html`은 로컬 전용 폴더 `ai/preview_html/`(git-ignored)의 `pdf_structure.html` 사본입니다. 이후 수정은 원본 쪽에서 하고 사본을 갱신해야 합니다.
- (3차) **숫자의 의미(슬롯 모델) 미구현**: 카드의 `▲ 3.1%` 같은 증감률·%p·건수, 원본 숫자 형식 유지, 비교 기준이 글자에 없는 증감 자리의 노란 표시는 아직 없음. 차트 축 의미·글자 없는 그림칸/막대 박스(도형을 VLM 에 전달)도 미구현. 이어서 할 일은 `docs/handoff_slot_model.md` 참고.
- (3차) VLM 은 호출마다 다르게 묶을 수 있음(예: 카드 두 장을 한 블록으로). 박스 위치는 정확하지만 묶음이 틀리면 경고만 붙음.
