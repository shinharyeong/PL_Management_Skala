# 실데이터형 시연 데이터 (로컬 전용)

로컬 Docker(compose) DB를 비우고, 실제 제출 양식 구조를 따른 합성 데이터를 실제 API 흐름(업로드 → 검증 → 조직 소명 → 제출 → 경영기획 수락·승인)으로 넣는다. 금액은 모두 합성값이다.

> **주의:** `run.sh`는 로컬 DB와 업로드 파일(`/data/storage`)을 지운다. 제출 양식(`/data/templates`)은 남긴다. 운영 DB에는 쓰지 않는다(로컬이 아닌 API 주소는 거부한다).

## 실행

```bash
bash scripts/dev-up.sh          # 로컬 compose가 꺼져 있으면 먼저
bash scripts/demo-data/run.sh   # 확인을 묻고 진행, 약 2~3분
```

끝나면 프런트(`docker compose port frontend 8080`, 보통 http://localhost:5173)의 `/dev`에서 계정을 골라 들어간다. 2027 연간 계획의 기한 경과 알림은 기한(실행 4분 뒤)이 지난 다음 예약 작업(5분 주기)이 돌아야 생긴다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `run.sh` | DB 비우기 → 조직·계정 SQL → 적재 → 11월 작업 상태 → 알림 정리 |
| `model.py` | 조직·항목·규모·계절성·계획값, 조직 SQL(`python3 model.py`로 출력) |
| `workbook.py`, `xlsx_xml.py` | 제출 엑셀(xlsx) 생성. 표준 라이브러리만 쓴다 |
| `seed.py` | 단계별 적재(`setup y2025 y2026 nov y2027`). 이미 된 단계는 건너뛴다. 사유가 있는 차이(`ACTUAL`), 추정 수정(`REVISE`), 재제출(`RESUBMIT`) 표가 여기 있다 |
| `extra.py` | 11월 Gap 상태(승인·재요청·회신·제외·선택), 재제출 요청, 보고서 소명 분류 |
| `readall.py` | 10월까지의 알림 읽음 처리 |

시나리오를 바꾸려면 `seed.py`의 `ACTUAL`·`REVISE`·`RESUBMIT`, `NOV_MODE`, `model.py`의 `W`(조직별 비중)를 고친 뒤 `run.sh`를 다시 실행한다.

## 알려진 문제

빈 DB에서 여러 조직 파일을 동시에 처음 올리면, 공용 답안지 항목(`report_item`)을 두 파일이 동시에 만들려다 한쪽이 `report_item_code_key` 중복으로 파싱 실패(`PARSER_INTERNAL_ERROR`)할 수 있다. 백엔드 `FinancialIngestionService`의 항목 생성이 "조회 후 없으면 저장"이라 생기는 문제다. `run.sh`는 이 경우 2025년 단계를 한 번 더 실행해 넘어간다.
