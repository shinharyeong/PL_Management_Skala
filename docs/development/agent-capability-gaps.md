# 기획팀 업무 대체를 위한 Agent 범위와 남은 도구

2026-11-27 기준. 사용자의 방향은 손익 조회 챗봇을 넘어 기획팀의 분석·판단 초안·보고서 작성·후속 질의 대응을 한 대화에서 처리하는 것이다. 아래는 현재 코드와 실제 읽기 검증을 기준으로 하며, 모델의 문장 품질과 업무 실행 완료를 구분한다.

## 현재 연결

Vue → Spring 대화 API → FastAPI LangGraph → 권한 제한 Tool → 기존 Spring 업무 서비스 → 실제 DB 순서다. Luna가 질문을 확인 항목으로 나누고 필요한 도구를 선택한다. 금액 집계·목표 비교·시나리오는 백엔드가 계산하고, 모델은 근거를 읽어 설명·해석·확인 질문을 작성한다. 기존 계산을 AI 내부에 복제하지 않는다.

현재 조회·초안·보고서 준비 도구는 19개다. 전사·조직·계획 차이·워터폴, 목표 검토, 승인 소명, 제출 버전·비교, 저장 분석·시나리오·업무 상태·요청 초안, 같은 실행의 원문 상세를 제공한다. 월간 손익·보고 항목 조회에 더해 기존 보고서 API를 사용하는 `report_templates`, `report_preview`, `report_export`와 전사 소명 API를 사용하는 `explanation_overview`를 연결했다. `plan_analysis`, `finish_answer`, `repair_answer`는 업무 조회가 아닌 계획·응답 제어 함수다.

- `monthly_pnl`: 선택 마스터의 기준월 실적. 전사 합계와 선택 조직을 구분하며 연간 전망과 섞지 않는다.
- `report_item_breakdown`: 조직×보고 항목 집계. 동일 제출본의 PLAN과 연간 전망을 비교한다. HOME의 확정 연간 계획과 다른 기준이며 원장 계정·전표 상세가 아니다. 전역 원천 최대 100개를 읽은 뒤 필터하므로 완전한 계정 목록이라고 주장하지 않는다.
- `report_templates → report_preview → report_export`: 같은 실행에서 실제 조회한 저장 틀의 버전을 선택하고, 고정 마스터와 일치하는 기존 보고서 값 채우기를 호출한 뒤 그 값을 그대로 XLSX로 준비한다. 파일은 현재 사용자에게만 10분간 서버 메모리로 제공한다. 틀·업무 데이터 저장과 발송은 하지 않는다.
- `explanation_overview`: 전사 분류별 Gap 합계·미분류 수락 소명·수락된 소명이 없는 항목을 조회한다. 조직 선택과 페이지는 상세에만 적용되며 전사 합계와 분리한다. 분류 합계 일치만으로 분류 완료를 판단하거나 수락 전 항목을 미회신으로 단정하지 않는다.

오른쪽 보고서는 목표 차이·조직 비교·근거 설명·불확실성·미해결 질문을 같은 응답으로 표시한다. 조회 성공과 설명 완료를 분리하고, 최종 요약만 검증에 실패했을 때 재검증된 개별 설명을 미완료 부분 결과로 남긴다. 해석의 인과적 진실성이나 개선 효과의 실현을 자동 보증하지 않는다.

## 모델보다 먼저 확인할 품질 조건

1. 기준: 보고서 전체가 동일 마스터·기간·단위를 사용하고 비교 계획의 출처를 명시한다.
2. 완전성: 조회 상한·누락·미회신·미검증 자료를 표시한다. 일부 결과를 전사 전체라고 일반화하지 않는다.
3. 숫자: 표시 금액·산식은 백엔드 원문으로 대사한다. 모델이 새로 쓴 금액을 검증된 계산으로 채택하지 않는다.
4. 설명: 사실·해석·개선 가설을 분리하고 각 문장에 근거를 연결한다. 의미 품질은 별도 사례 평가가 필요하다.
5. 실행: 초안, 사용자 승인, 실제 API 실행, 완료 확인을 구분한다. 답변 문장만으로 발송·승인을 완료 처리하지 않는다.

## 권장 개발 순서와 완료 기준

연결된 보고서 파이프라인은 실제 사용할 틀이 준비된 환경에서 전체 다운로드를 검증한다. 다음 읽기 범위는 월 마감 현황·다기간 비교·원천 상세다. 실제 기획 질문 묶음으로 요구 항목 해결률, 숫자·근거 일치율, 반복 호출·완료 시간, 누락 자료 안내를 평가한다. 모델 교체 자체는 이 평가의 완료 기준이 아니다.

다음으로 요청·회신·결재 업무를 승인 대기 단계와 함께 연결한다. 중복 요청, 잘못된 조직, 권한 변경, 보완·미회신, 기준 버전 변경, 도중 재시작을 검증한다. 운영 DB 읽기만 허용된 현재 검증에서는 이 상태 변경을 실행하지 않는다.

ERP는 이후 원천 실적·조직·계정과 계약·수주 자료의 대사를 위한 연결이다. ERP가 없어도 제출·소명 자료로 보고서 초안을 작성할 수 있지만, 그 자료에 없는 계약 조건·미래 인식 가능액·실제 개선 효과를 확정할 수는 없다.
