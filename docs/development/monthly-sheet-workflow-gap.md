## 1. 유지할 업무 요구

연간 계획은 연 1회 수행하는 별도 업무이고 월간 시트 관리가 주업무다. 연간 업무 내 정정·재제출의 상세 정책은 별도로 정한다. 월간 기능의 구현 진척을 연간 제출 기능의 구현 수로 대신 설명하지 않는다.

월간 경영기획팀의 기본 흐름은 다음과 같다.

1. 요청 현황에서 조직을 선택해 해당 조직의 월간 계산기로 이동한다.
2. 대상 기간·조직·비교 기준·비교 대상을 확인하고 금액 조건을 적용해 변경 항목을 조회한다.
3. 사용자가 소분류 또는 세부분야를 체크하고 명시적으로 **장바구니에 담기**를 실행한다.
4. 왼쪽 `월간 시트 관리` 아래에 생긴 조직별 작업공간에서 담긴 항목을 확인한다.
5. 같은 조직 작업공간에서 셀 단위 비교, 선택 항목 소명 요청, 회신 확인, 재요청·재검토와 이력을 이어간다.

### 금액 조건과 소명 대상

- 차이율과 최소 금액 조건은 각각 켜고 끌 수 있다.
- 두 조건을 모두 켰을 때 AND로 적용하는 것은 **현재 123의 예시 계약**이다. 구현 계약 확정 시 이 규칙을 명시적으로 확인한다.
- 조건을 모두 끄면 금액 조건 없이 **전체 변경 항목**을 보여 주고 사용자가 요청할 대상을 선택한다. 변경이 없는 모든 셀을 뜻하지 않는다.
- 필터에 걸렸다는 사실, 체크했다는 사실, 장바구니에 담았다는 사실만으로 소명이 발송되거나 필수 소명 상태가 되지 않는다.
- **소명 요청은 사용자가 선택한 항목에 대해서만 명시적으로 실행한다. 모든 금액 변경을 자동 필수 소명 대상으로 만들지 않는다.**
- 적용 대상이 영업이익(OP)뿐이라는 규칙도 제품 요구로 확정하지 않는다. 화면의 보고 항목·소분류·원천 셀 사이의 선택 및 요청 단위를 정의해야 한다.

필터 변경은 현재 조회 결과만 바꾼다. 이미 담긴 항목·요청·회신 이력을 지우거나 기준을 덮어쓰지 않는다.

## 2. 현재 코드가 제공하는 범위

현재 서비스 API 35개 설계 경로 중 17개가 구현되어 있지만, 이는 **공통 기능과 최초 연간 제출을 포함한 수치이며 월간 시트 관리의 진척률이 아니다**. 현재 완료 가능한 업무 연결은 최초 연간 PLAN의 접수·파싱·명시적 검증·적재·최종 제출과 기획자 조회다. 월간 검증은 `MONTHLY_VALIDATION_UNAVAILABLE` 진단을 추가해 검증 충족·최종 제출 가능 상태가 되지 못하게 한다. API 호출 자체를 모두 거부한다는 뜻은 아니다. [S2][S3][S4]

| 구분 | 확인한 구현 | 월간 연결 시 주의점 |
| --- | --- | --- |
| 사용자·조직 조회 | `/me`, `/organizations`, 역할별 조직 접근 제한 | 기획자는 전체, 조직 담당자는 본인 조직만 접근한다. |
| 요청 등록·조회 | 요청 생성·목록·상세와 대상별 최신 최종 제출본·초안 수 | 현재 등록은 모든 활성 조직 대상이다. 수신자 선택·발송을 구현한 것으로 표시하지 않는다. |
| 전체 파일 접수 | 원본 저장, 새 DRAFT, 파싱 작업 접수 | 업로드 성공은 최종 제출·승인 성공이 아니다. |
| 파싱·진단·원본 | 상태 폴링, 진단, 후보 조회, 원본 다운로드, 보존한 원본 셀 조회 | 월간 업무 검증이나 비교·소명 기능의 완료를 뜻하지 않는다. |
| 운영 오류 재파싱 | `retryAllowed`인 동일 원본의 재파싱 | 원본을 유지하고 파싱 시도를 늘린다. 모든 파일 오류에 허용하지 않는다. |
| 검증·금액 조회 | 최초 연간 PLAN의 명시적 검증과 유효 상세 적재·보고 집계 | 월간에 같은 검증이 이미 존재한다고 가정하지 않는다. |
| 상태·동시성 | 상태 토큰, 검증 현재성, 멱등 명령과 충돌 응답 | 새 월간 명령에도 같은 원칙을 확장해야 한다. |
| 월간 작업공간 | 저장·담기·조회 계약 없음 | 별도 API·저장 모델이 필요하다. |
| 소명·승인·공식 master | 전체 설계에 있으나 서비스 구현은 후속 범위 | 문서의 예시 응답을 실제 실행 가능한 API로 취급하지 않는다. |

### 현재 제약과 제품 요구의 구분

| 현 구현의 제약 | 실제 동작 | 필요한 조율 |
| --- | --- | --- |
| 월간의 확정 연간 계획 선행 조건 | 월간 요청 생성은 연간 계획의 CONFIRMED 상태를 요구하고, 월간 업로드는 추가로 해당 조직의 확정 계획본을 요구한다. 현재 연간 확정 API는 없다. [S5][S6] | 연간 별도·월간 주업무 요구에 맞는 진입 및 비교 기준 계약을 정한다. 현 제약을 월간 전체의 확정 선행 조건으로 자동 수용하지 않는다. |
| 모든 활성 조직 대상 요청 | 요청 DTO에 대상 조직 배열이 없고 서버가 활성 조직 전체를 등록한다. [S5] | 사용자 선택 대상에 대한 월간 요청과 기존 전 조직 제출 요청을 어떻게 구분·확장할지 정한다. |
| 조직 단위 PENDING 잠금 | 검토 중인 제출본이 있으면 해당 조직의 새 접수·최종 제출을 제한한다. [S6] | 다른 요청·대상 월·버전의 병행 작업을 허용할 범위를 정한다. 조직 작업공간의 조회·항목 모음까지 동일하게 잠그지 않는다. |

이 제약은 현재 API 연결 시 표시해야 할 실제 제한이다. 이 문서만으로 기존 가드를 제거하거나 월간 기능이 실행된다고 응답하지 않는다.

## 3. 기존 설계 문서와 정합성을 맞출 항목

현재 API 계약에는 모든 금액 변경의 소명 의무와 확인된 OP에 대한 Gap 규칙이 남아 있다. 현재 검증 코드도 이전 금액 구성이 달라지면 `CHANGE_EXPLANATION_REQUIRED`로 차단한다. 이는 사용자가 정정한 **필터 조회 후 수동 선택·요청**과 충돌한다. [S3][S7]

| 기존 내용 | 이번 요구 기준 처리 |
| --- | --- |
| 모든 수정 금액에 자동 필수 소명 | 제품 요구로 채택하지 않는다. 비교 탐지와 사용자 소명 요청을 분리하도록 도메인·API·검증 규칙 수정이 필요하다. |
| 손익 Gap은 OP에만 적용 | 제품 요구로 확정하지 않는다. 어떤 보고 항목·세부분야를 필터링하고 어느 단위에 요청할지 새 계약에서 정한다. |
| 체크·선택 검토와 업무 상태 변경 연결 | 체크는 임시 선택, 담기는 작업공간 저장이다. 검토 완료·발송·수락·승인을 자동 발생시키지 않는다. |
| 숫자 변경과 소명 대상의 동일시 | 변경 탐지 결과와 실제 요청 집합을 각각 식별한다. 요청 대상은 사용자의 명시적 선택으로 정한다. |

관련 수정 대상은 `docs/domain-rules.md`, `docs/flow.md`, `docs/development/erd.md`, `docs/development/api-contract.md`, `docs/development/backend-integration.md`, 관련 검증 코드와 인수 조건이다. **이번 문서 PR은 이 파일들을 일괄 수정하거나 구현 정책을 바꾸지 않는다.** 변경 범위는 후속 설계·개발 PR에서 합의한다.

## 4. 데이터와 비교 계약

### 항목 식별과 셀 위치

- 제출본 ID는 전체 원본 스냅샷을 식별한다. 버전 표시명과 제출일·승인일은 별도 필드다.
- 검토 항목은 조직·보고 항목·대상 연월·시나리오 및 필요한 세부분야 식별자를 포함해야 한다. 최종 고유 키는 매핑·집계 규칙과 함께 확정한다.
- 시트·셀 주소는 원천 근거 위치다. 행 이동·정렬만으로 다른 업무 항목이라고 단정하지 않는다.
- 상세 ID가 확인되면 ID와 개정 정보를 사용한다. 확인되지 않으면 대응 관계가 미확정임을 표시하고 임의의 이전 행→현재 행 짝을 만들지 않는다.
- 동일 이름의 항목을 이름만으로 병합하지 않는다. 상위 합계와 하위 상세를 함께 더하거나 중복 요청하지 않도록 요청 단위를 정한다.

### 비교 스냅샷

계산 결과와 담긴 항목은 최소한 다음 문맥에 연결한다. 저장 방식과 토큰명은 제안이며 기존 DTO에 구현된 필드로 가정하지 않는다.

| 문맥 | 보존할 의미 |
| --- | --- |
| 조직·업무 기간 | 조직 ID, 요청 ID가 있으면 해당 ID, 선택한 대상 연월 |
| 기준·비교 원본 | 각 제출본 ID, 확인된 업무 버전, 데이터 개정 토큰·파싱 시도 등 결과 현재성 근거 |
| 기준·비교 시나리오 | 각 원본의 PLAN/ACTUAL/ESTIMATE와 대상 연월. 파일 버전과 시나리오를 구분한다. |
| 조회 조건 | 켠 조건과 값·단위, 비교 방향, 적용 당시 정책 버전 |
| 선택 항목 | 안정적인 보고·상세 항목 참조와 원천 위치 |
| 계산 결과 | 적용한 두 값·차액·차이율 및 미확정 사유 |

계획 열과 실적 열을 각각 v1·v2라고 부르지 않는다. 같은 파일의 서로 다른 시나리오 비교와 제출 버전 사이 비교를 표시와 계약에서 구분한다. 원본이나 파싱 시도가 바뀌면 기존 계산의 현재성을 확인하게 하되 담긴 항목을 조용히 삭제하거나 최신 기준으로 교체하지 않는다.

### 금액과 미확정 값

- 계산은 서버 또는 명시적인 코드 경로에서 정확한 십진 값으로 수행한다. LLM과 표시용 반올림 값으로 계산하지 않는다.
- API 금액은 정밀 십진 문자열을 사용하고 업무 금액의 기준 단위와 원본 단위·배율을 구분한다. 단위 미확정 후보에 임의로 ‘원’을 붙이지 않는다. [S3][S8]
- 실제 0, 빈 값, 미수집, 미확정, 적용 대상 아님을 구분한다. 미확정 값을 0으로 합산하지 않는다.
- 차액 방향, 음수 기준의 차이율, 기준값 0의 차이율·필터 통과 여부, 임계값의 초과/이상 경계, 두 조건을 모두 끈 경우의 변경 정의는 **정책 결정 항목**이다. 기준값 0을 무한대나 0%로 임의 확정하지 않는다.
- 현재 source-cells는 파서가 submissionData.sourceCells에 수집·보존한 근거 셀만 조회한다. 임의의 전체 Excel 셀 탐색이나 버전 간 대응을 제공하지 않으며 없는 위치는 SOURCE_CELL_NOT_FOUND다. 원본 수식·저장 캐시·정규화 값·단위·배율·공유 수식 기준을 근거로 조회한다. 보존된 수식 조회와 수식 재계산을 구분한다. [S8]

### 월간 데이터의 사용 가능 조건

현재의 최초 연간 검증 결과를 월간 검증 결과로 대체하지 않는다. 파싱 SUCCEEDED만으로 월간 비교에 필요한 조직·기간·단위·보고 분류·전체 범위가 확인됐다고 판단하지 않는다.

월간 비교에 사용할 수 있는 원본·후보·적재 값의 자격과 불완전한 경우의 조회 범위를 별도로 구현해야 한다. 권장 방향은 비교 응답에 사용 가능한 범위와 차단 사유를 반환하고, 금액 확인이 안 된 항목을 정상 결과로 섞지 않는 것이다. 월간의 명시적 수동 `validation` 단계 추가를 사용자 업무의 필수 단계로 확정하지 않는다.

계산기의 다운로드 버튼은 비교 스냅샷·단위·필터 범위를 고정해 내보내는 계약이 추가로 필요하다. 파일 형식과 원본/가공 자료의 구분은 후속 항목이며 현재 보고서 API나 원본 다운로드가 이를 대신 구현한 것으로 보지 않는다.

API 예시 본문·성공 응답을 확정하기 전에 다음을 결정한다.

1. 월간 원본의 사용 가능 조건과 확정 연간 계획 선행 가드의 적용 범위.
2. 요청 가능한 세부분야·원천 상세의 고유 식별자 및 비교 대응 관계.
3. 필터 논리·기준값 0·미확정·임계값 경계·변경 정의.
4. 작업공간 소유·조직별 공유·기간/버전 묶음·중복 담기 정책.
5. 소명 요청의 생성·알림 전송·회신·재검토와 제출본 승인 사이의 경계.

## 7. 권한·동시성·처리 결과

- PLANNER는 허용된 조직의 비교·담기·요청·회신 검토를 수행한다. ORG_MANAGER는 본인 조직 요청과 근거만 조회·답변한다. 구체적인 조직 간 기획자 권한 범위는 작업공간 공유 정책과 함께 정한다.
- 조직 ID를 화면 필터·요청 본문에 넣었다는 이유로 접근을 허용하지 않는다. 작업공간→담긴 항목→원본→소명→첨부의 전체 경로에서 조직 소속을 확인한다.
- 담긴 항목과 요청 대상은 서버에서 비교 스냅샷·조직·허용 상태를 다시 확인한다. 클라이언트가 금액·조직·소명 상태를 임의 지정하지 못하게 한다.
- 기존의 명령 멱등키와 최신 상태 토큰 원칙을 새 저장·요청·검토 명령에 확장하는 것을 제안한다. 같은 요청의 재시도와 다른 요청을 구분하고, 충돌 시 현재 상태를 조회한다. [S9]
- 오래된 비교·새 파싱 시도·다른 사용자의 변경이 감지되면 수정 이유와 재확인 경로를 제공한다. 구시도 결과를 현재 결과처럼 남기거나 자동 재발송하지 않는다. 현재 공통 구현의 검증 현재성 판정은 참고할 수 있으나 월간에 이미 연결된 기능은 아니다. [S10]
- 처리 중 중복 클릭, 응답 유실, 요청 저장 성공 후 알림 실패를 별도 상태로 다룬다. 실제 발송 구현체와 재시도 정책은 미정이다.

## 8. 소명·재제출·승인·master의 경계

| 작업 | 보존·변경 범위 |
| --- | --- |
| 장바구니 담기 | 작업 항목과 비교 문맥을 저장한다. 숫자·소명 발송·검토 완료·승인을 변경하지 않는다. |
| 소명 요청·회신·보완 | 선택 항목의 요청과 설명 회차를 보존한다. 기존 제출본에 설명을 추가하는 보완을 파일 재제출과 구분한다. |
| 파일 재제출 | 조직의 전체 파일을 새 제출본으로 접수한다. 기존 원본·숫자·이력을 덮어쓰지 않는다. 현재 공통 접수의 보존 원칙을 유지하되 월간 허용 조건은 조율한다. |
| 소명 수락 | 설명 검토 결과를 남긴다. 제출본 승인·금액 변경·master 발행과 별개다. |
| 제출본 승인·공식 master | 현재 서비스 미구현 범위다. 선택 항목 수락을 조직 전체 승인으로 간주하지 않는다. |

기존 master 설계의 최초 전 조직 승인 후 발행·후속 승인 조직별 교체 규칙은 검토 대상 계약으로 참조한다. 이 문서가 승인·발행 정책의 신규 확정이나 구현을 뜻하지 않는다. 선택 항목 요청 흐름과 전체 제출본 승인 조건의 연결은 별도로 합의한다. [S3]

## 9. QA 인수 조건

아래는 후속 개발의 인수 조건이며 현재 코드·문서 PR에서 통과한 테스트 목록이 아니다. 금액과 조직은 모두 합성 값으로 검증한다.

| 사례 | 기대 결과 |
| --- | --- |
| 차이율만 켜기 / 금액만 켜기 | 켠 조건만 적용하고 적용 조건을 결과에 표시한다. |
| 두 조건 모두 켜기 | AND 예시 계약을 채택한 경우 두 조건을 모두 충족하는 변경만 보여 준다. |
| 두 조건 모두 끄기 | 금액 조건 없이 전체 변경을 조회한다. 자동 전체 소명을 생성하지 않는다. |
| 조회 결과 중 2개 선택·담기 | 담긴 2개만 조직 작업공간에 추가한다. 요청 발송·검토 완료·승인이 발생하지 않는다. |
| 담은 뒤 필터 변경·해제·재계산 | 기존 항목·비교 문맥·요청 이력이 보존된다. 신규 조회 결과와 이미 담긴 항목을 구분한다. |
| 담긴 3개 중 1개만 소명 요청 | 선택한 1개만 요청 대상이다. 필터 결과 전체나 담긴 전체를 자동 포함하지 않는다. |
| 새로고침·다른 메뉴 이동 | 합의한 보존 범위에서 조직 탭과 항목·대상 기간을 복원한다. 임시 저장이라면 그 범위를 명시한다. |
| 같은 추가 명령 반복·응답 유실 | 합의한 중복 키와 멱등 정책에 따라 중복 항목·중복 요청을 만들지 않는다. |
| 다른 월·다른 비교 버전의 동명 항목 | 기존 항목을 덮어쓰지 않고 구분한다. 이름·셀 주소만으로 병합하지 않는다. |
| 상세 ID 유지 상태의 행 이동 | 셀 위치 변경과 업무 항목 변경을 구분한다. ID 미확정이면 임의 대응쌍을 만들지 않는다. |
| 조직 A의 항목을 조직 B 작업공간에 추가·조회 | 서버가 거부하고 원본·소명·첨부도 노출하지 않는다. |
| 기준 0 / 누락 / 미확정 / 실제 0 | 각 상태를 구분한다. 기준 0의 비율·필터 통과는 확정 정책으로 검증한다. |
| 단위·정밀도 | 예: 원 100000000과 억원 1을 같은 값으로 환산하되 원본 단위·배율을 보존한다. 표시 반올림 전 값으로 판정한다. |
| 부분 원천 확인·불완전 합계 | 확인된 근거와 미확정 결과를 구분하고 일부 행만 다시 합산해 정상 전체 금액으로 표시하지 않는다. |
| 파싱 시도·원본 문맥 변경 | 기존 비교의 현재성을 확인하게 한다. 새 기준을 조용히 적용하거나 담긴 항목을 삭제하지 않는다. |
| 소명 보완 | 같은 제출본의 설명 회차를 남긴다. 금액·파일·제출 회차·master를 변경하지 않는다. |
| 파일 재제출·소명 수락·제출본 승인 | 각각의 대상·효과·권한을 구분한다. 실제 미구현 명령을 성공 처리하지 않는다. |
| 충돌·동시 작업 | 오래된 토큰 명령을 거부하고 최신 상태와 선택 문맥을 재확인한다. 자동 재발송하지 않는다. |
