# 원본 근거와 의미 매핑 규칙

## 범위와 구현

구현은 `src/excel_parser/mapping.py`의 `map_workbook(workbook, metadata=None)`입니다. `extraction.extract_workbook`의 메모리 결과를 받아 표준 레코드, 진단, 집계, GAP 지표 관계를 반환합니다. 이 모듈은 파일 읽기·쓰기, 수식 계산, DB 저장을 수행하지 않습니다.

전체 원본 보존과 재무 의미 매핑은 다른 단계입니다. 파일·조직·시트 개수는 입력에서 읽으며 고정 전제로 사용하지 않습니다. 이 문서는 파서 규칙과 검증 방법만 설명하며, 실제 입력 파일명·조직 식별자·셀 위치·원본 값·특정 실행의 조사 결과는 포함하지 않습니다.

## 지원하는 표 구조

시트 이름만으로 표를 판정하지 않습니다. 다음 원본 헤더 조합을 확인해야 해당 규칙을 적용합니다. 헤더 위치와 연도·월은 값에서 읽습니다.

| 원본 구조 | 식별 근거 | 의미와 주의점 |
| --- | --- | --- |
| 매출 상세 | `조직명`, `관리분류`, `중분류`, `소분류`; 연도/시나리오 헤더와 월·연간 헤더 | `사업부코드` 열은 선택 사항. 없으면 같은 원본 코드표의 유일한 이름 대응으로 확인하고, 확인 불가·충돌은 미확정으로 보존 |
| OpEx 상세 | `대분류`, `중분류`, `소분류`, `조직명`, `예산Code`; 연도/시나리오 헤더와 월·연간 헤더 | 예산코드, 팀, 실행과제, 비용구분, 실적집계기준, 거래내역을 각각 보존. 헤더 위치는 입력에서 확인 |
| 재무 답안지 | 연도·계획/실적/추정·분기/연간·월의 다단 헤더 | 왼쪽 항목 열의 들여쓰기를 항목 경로로 읽음. 표준값은 합계·소계로 분류하며 상세와 중복 합산하지 않음. 월 없는 분기 열은 `aggregation=quarter`로 매핑하고 월·연간과 합산하지 않음 |
| 사업부별 집계 | 사업부코드·사업부명과 `<연도> <시나리오> <항목>` 형태의 복합 헤더 | 조직별 연간 요약. 전체 합계 행도 보존하며 조직 행과 구분 |
| 코드표·참고 시트 | 위 재무 구조에 해당하지 않는 표 | 원본은 모두 보존. 숫자나 수식 후보도 표준 목록에 남기되 재무 의미 미확정으로 구분 |

단위·기간·시나리오 설명이 있는 경우 표 자체의 헤더·수식과 대조합니다. 설명의 위치를 고정된 셀 주소로 가정하지 않습니다. 통합 파일의 집계 범위나 내부거래 제거 여부도 명시된 근거 없이 추정하지 않습니다.

## 적용 규칙

| 규칙 ID | 내용과 근거 |
| --- | --- |
| `MAP_REVENUE_DETAIL` | 매출 상세 헤더를 확인하고 행의 조직코드·조직명, 관리·중·소분류와 값 열을 연결 |
| `MAP_EXPENSE_DETAIL` | OpEx 상세 헤더를 확인하고 예산코드·항목명·추가 차원과 값 열을 연결. 숫자 예산코드와 조직명 수식 캐시는 금액으로 변환하지 않음 |
| `MAP_FINANCIAL_STATEMENT` | 답안지의 항목 계층과 다단 기간 헤더를 연결. 월 값과 연간 값을 구분 |
| `MAP_ORGANIZATION_SUMMARY` | 복합 헤더의 연도·시나리오·항목과 행의 조직을 연결 |
| `MAP_UNKNOWN` | 지원 표 구조를 확인하지 못한 후보. 값·수식과 출처를 보존하고 재무 의미를 확정하지 않음 |
| `PERIOD_GROUP_HEADER_SCENARIO` | 상세의 연도군 제목이 소속 월·연간 열의 시나리오를 정함. 아래 연간 라벨과 표현이 달라도 연도군 제목의 명시 근거를 보존 |
| `PERIOD_CROSS_SHEET_MONTH_SCENARIO` | 상세의 실적 또는 실적/추정 혼합 연도군을 같은 워크북 답안지의 동일 연월에 명시된 시나리오로 보완. 계획군을 변경하거나 전환 월을 고정하지 않음 |
| `PERIOD_CROSS_SHEET_SCENARIO_CONFLICT` | 같은 원본의 동일 연월에 실적·추정 근거가 충돌하면 월과 관련 연간 시나리오를 `unknown`으로 남김 |
| `PERIOD_ANNUAL_MIXED_COMPONENTS` | 연간 헤더의 시나리오와 연결 월별 값의 시나리오를 대조. 실적·추정이 함께 있으면 연간은 `mixed`로 표시하고 원본 헤더는 그대로 보존 |
| `UNIT_SUBTOTAL_THOUSAND_TO_HUNDRED_MILLION` | 상세 상단 `SUBTOTAL(...)/100000` 또는 `/10^5`는 천원 상세를 억원으로 환산한 결과. 상세 제목의 천원 단위를 다시 적용하지 않음 |
| `TEXT_INTEGER_GROUPING_FROM_SOURCE_FORMAT` | 금액 문자열·명시 KRW 단위·회계 여백을 제거한 양수 서식 `#,##0` 또는 `#,##0.0`처럼 점 뒤 0이 하나 이상인 서식·정확한 3자리 쉼표 그룹이 모두 일치할 때만 `ko_KR` 정규화를 사용. 문자열의 점 이하 소수 정밀도도 보존 |
| `UNIT_SUBTOTAL_CONVERSION_UNRESOLVED` | 상세 상단 소계의 단위 변환이 지원된 수식 근거와 다르면 단위를 미확정으로 남김 |
| `FORMULA_CACHE_UNAVAILABLE` | 캐시 누락·오류 수식은 원문과 출처를 남기며 값을 0으로 대체하지 않음 |
| `GAP_PREFER_EXPLICIT_NO_AUTOMATIC_ADJUSTMENT` | 명시된 Contingency 제외 영업이익이 있으면 그 원본 레코드를 우선 연결. 추가 조정값을 계산하지 않음 |

병합 헤더는 기준 셀 주소와 상속 대상 행·열·병합 범위를 `period.provenance[].inheritance`에 기록합니다. 헤더 해석 때문에 원본 빈 셀을 생성하거나 금액을 복제하지 않습니다.

## 출처·항목·정규화

- 모든 표준 레코드의 `source.raw_record_id`는 추출된 원본 셀을 가리킵니다. 파일 식별자·입력 경로·시트·셀도 함께 제공합니다.
- `raw_value`와 `formula`는 원본 값과 수식/캐시 상태를 그대로 보존합니다. 수식 캐시는 재계산 결과가 아닙니다.
- `item.code`는 비용의 원본 예산코드 또는 매출 중분류의 명시적인 선행 숫자 코드를 사용합니다. 원본 항목코드가 없으면 임의 발급하지 않습니다. 영업이익 등 확인된 지표에는 아래 지표 코드가 들어갈 수 있습니다.
- 설명 셀에 명시된 `[ID:...; 수정:N]`은 `item.detail_id`, `item.detail_revision`으로 보존하고 근거 셀도 함께 남깁니다. ID 문자열의 조직 부분을 읽어 조직코드를 보완하지 않습니다. 수정본 선택은 매핑이 아닌 별도 조립기의 책임입니다.
- `item.metric_code`는 GAP 지표 식별용 `OP`, `CONTINGENCY`, `OP_EX_CONTINGENCY` 또는 null입니다. 원본 예산코드와 별개로 유지합니다. 영업이익률을 영업이익 금액으로 분류하지 않습니다.
- 항목 계층은 `item.header_path`, 실제 구분 차원은 `dimensions`에 근거 셀과 함께 남깁니다. 동일 항목명이더라도 차원이 다르면 같은 레코드로 합치지 않습니다.
- 정상 숫자의 내부형은 `Decimal`입니다. `value.normalized_value`와 `value.multiplier`는 저장 계층에서 십진 문자열로 직렬화해야 합니다. 숫자 서식과 스타일은 `style_reference` 및 원본 스타일 자료를 참조하며 반복적인 표시 형식 해석 전체를 각 레코드에 복제하지 않습니다.
- 금액은 명시된 원·천원·백만원·억원을 원 기준으로 정규화합니다. 비율은 원본 숫자에 백분율 배율을 다시 적용하지 않습니다. 원본 값·원본 단위·적용 배율은 별도 필드로 남습니다.
- 비율 판정: `%` 표시 서식이면 비율로 확정합니다. 서식은 아니지만 항목명이 비율(끝이 `률`·`율`, `비율`·`%` 포함)이면 `value_kind=ratio`로 두고 금액 단위 배율을 곱하지 않되, 저장값의 백분율 여부를 알 수 없으므로 `normalized_value=null`, 상태 `unresolved`, 규칙 `RATIO_ITEM_NAME_FORMAT_UNCONFIRMED`로 남깁니다.

## 조직·제출 정보와 집계 제한

조직은 실제 상세 행의 코드·원래 이름에서 읽습니다. 같은 워크북의 조직 코드표만 보조 근거로 사용합니다. 여러 조직 상세와 조직별 집계 구조가 함께 있는 파일은 `source.workbook_role=consolidated_reference`, 단일 조직 상세 파일은 `organization_workbook`으로 표시합니다. 이는 승인 완료나 공식 마스터 지위를 뜻하지 않습니다. 통합 파일에서 조직 파일의 숫자를 가져오지 않습니다.

원본 조직 코드·이름 셀이 Excel 오류 타입이거나 수식 캐시가 `error`/`missing`이면 정상 문자열·빈 조직명으로 해석하지 않습니다. 수식 조회 오류는 `ORGANIZATION_LOOKUP_ERROR`, 수식 없는 오류 셀은 `ORGANIZATION_VALUE_ERROR`로 남기며 `organization.status=unresolved`입니다. 오류인 code/name은 미확정으로 두고 `original_name`과 원본 근거는 보존합니다. 다른 정상 행의 공통 조직이나 제출 메타데이터로 덮어쓰지 않습니다. 코드표 자체의 오류·캐시 누락 셀도 정상 조직 등록 근거로 쓰지 않습니다. 실제 코드·이름 충돌과 동명 모호성은 기존 진단을 유지하며, 모든 조직 진단은 해당 행의 조직 근거를 `diagnostics.cell`에 제공합니다.

조직 코드표는 `사업부코드`와 `사업부명`을 가진 원본 표에서 읽습니다. 같은 코드에 서로 다른 이름이 있거나 같은 이름에 여러 코드가 연결되면 충돌·모호 상태를 보존합니다. 명시 코드와 행 이름이 코드표와 충돌할 때도 원문을 유지하며 조직이 확정되었다고 표시하지 않습니다. 코드가 비어 있을 때만 같은 원본의 유일한 이름 대응을 사용합니다. 근거 없는 파일명 코드, 다른 조직의 파일, 평가용 마스터는 보완에 쓰지 않습니다.

`metadata`는 기존 `organization_code`, `organization_name`, `submission_month`, `submission_version`, `submission_cycle`, `revision`, `locale`과 선택 표식 `organization_verified`를 받습니다. 함수 시그니처와 기존 필드명은 유지하지만, 조직 보완을 사용하려는 호출자는 **확인된 메타데이터에만 `organization_verified=True`를 명시**해야 합니다. 표식이 없는 조직 메타데이터는 `ORGANIZATION_METADATA_UNVERIFIED` 진단과 함께 보완에서 제외합니다. 확인된 메타데이터라도 원본의 확정 조직과 충돌하면 원본을 유지하고 `ORGANIZATION_METADATA_CONFLICT`를 남깁니다. 표식 자체가 외부 근거 검증을 대신하지 않으므로 호출자가 확인 책임을 가집니다.

제출 월은 `YYYY-MM`, 버전은 문자열이어야 합니다. 합성 예시 `V1.01`은 원문을 유지한 채 회차 1·개정번호 1로 분리할 수 있습니다. 버전 문자열을 소수로 저장하지 않습니다. 대상 연월에서 제출 월을 유추하지 않습니다.

상세·소계·합계·비율·참고의 역할과 월·연간 집계 차원을 각각 제공합니다. `role.aggregatable=false`는 현재 계약에서 모든 레코드의 일괄 합계를 허용하지 않는다는 뜻입니다. 조직·제출본·대상 기간·시나리오·단위·항목·추가 차원을 고정하고 상세/합계 중복과 통합 참고 파일 중복을 제거하는 정책은 후속 소비자가 정해야 합니다. 현재 파서는 전사 마스터를 발행하거나 업무 승인 상태를 만들지 않습니다.

### 입력하지 않은 비용 양식 행

`role.kind=inactive_template`은 지원하는 비용 양식의 **미사용이 확인된 행**입니다. 단순히 금액이 0이거나 조직이 없다는 이유로 지정하지 않습니다. 다음 조건을 모두 만족해야 합니다.

- 실제 헤더로 확인한 대분류·중분류·소분류·조직·본부·팀·과제·예산·실적집계기준·비용구분 등 정해진 양식 구조가 있습니다.
- 조회 셀 10개가 같은 행의 팀/과제/예산 입력을 참조하는 알려진 `INDEX/MATCH` 또는 `VLOOKUP` 식이며, 원본 타입이 오류이고 캐시가 `#N/A`입니다. 외부 참조·다른 범위·임의 수식·다른 오류는 미사용 근거가 아닙니다.
- 모든 연간 셀이 같은 행의 해당 연도 1~12월 연속 범위를 합하는 `SUM`이며 저장된 숫자 캐시가 0입니다. 공유 수식은 같은 열의 base 주소·si·범위와 상대 행을 확인합니다. 공유 범위를 벗어나거나 고정된 다른 행을 참조하면 미사용으로 확정하지 않습니다.
- 연도와 월별/연간 시나리오가 확인되고 서로 호환됩니다. 혼합 연간은 actual/estimate 월 구성을 허용합니다. unknown 기간은 미사용 판정에서 제외합니다.
- 월별 값·수식이 모두 없고 나머지 식별 입력·분류·담당자·설명·추가 열·주석도 없습니다. 직접 입력한 0, 공백 문자열, 캐시 0인 월 수식도 실제 입력으로 취급합니다.

이 역할은 원본·후보를 삭제하지 않습니다. `source`, `raw_value`, `formula`, `value`, `period`와 후보 순서·개수를 유지하고, `mapping.status=unmapped`, `mapping.rule_ids`의 `ROW_INACTIVE_EXPENSE_TEMPLATE`로 판정 근거를 구분합니다. 조직 충돌 경고와 상세 업무키 검증만 미사용 행에서 제외합니다. 실제 입력 행은 기존 상세 검증을 계속 수행합니다. 내부 브리지가 상세 검토 대상을 고를 때 이 역할을 제외하는 것은 합계 승인이나 전체 제출 완전성 검증과 다릅니다.

`_template_formula`는 수식과 공유 범위를 확인하고 `_inactive_expense_template_row`는 위 조건을 판별합니다. `map_workbook`이 행별로 결과를 캐시해 `_row_context(..., inactive_template=...)`에 전달합니다. `_row_context`를 직접 호출하는 기존 경로는 생략 시 동일 판별을 수행합니다.

메모리 회귀는 `test_mapping_monthly.inactive_expense_workbook`의 정상 0원 행과 조회 오류·공유 연간 SUM만 남은 행을 사용합니다. `test_unused_expense_formulas_preserve_candidates_and_active_zero`, `test_any_real_input_or_month_formula_keeps_expense_row_active`, `test_unknown_or_broken_formula_does_not_prove_unused_template`, `test_missing_organization_formula_cache_never_uses_fallback`이 후보/금액/수식 보존, 실제 0·월 수식·공백·식별 입력·추가 열·주석, 공유 범위·다른 행 참조·캐시 누락, 공통 조직으로 오류를 덮지 않는 동작을 검증합니다. 파일·캐시·로그·변환본을 만들지 않습니다.

별도 `master.assemble_master`는 월별 상세만 골라 명시한 제출·수정본 정책으로 기술 마스터를 조립합니다. 공식 승인이나 업무 버전을 발급하지 않으며 `business_master_issued=False`를 유지합니다. 같은 조직을 다시 제출하면 그 조직 상태 전체를 교체하고, 최고 수정번호 행이 여러 개일 때는 **해당 행의 전체 월별 의미·정규금액·상태가 모두 같은 경우에만** `exact_duplicate_delivery`로 한 번 반영합니다. 모든 중복 출처와 건수, 제외한 구개정 원본을 보존합니다. 어느 월이라도 내용이 다르면 해당 상세행의 선택이 미확정입니다.

조립 입력을 만드는 `benchmark.reconstruction.parse_submission`은 제출 소유 조직과 각 상세행의 조직을 구분합니다. 월별 상세의 비어 있지 않은 조직코드 집합이 하나면 기존 유일 행 조직을 소유자로 유지합니다. 서로 다른 코드가 둘 이상일 때만 `_source_declared_owner`로 상단 선언을 확인합니다. 확인된 `financial_statement`의 데이터 시작 전·첫 금액 열 왼쪽에 `▣ 조직명` 제목과 같은 이름의 별도 셀이 모두 있고, 같은 원본 코드표에서 그 이름과 코드가 유일하게 대응해야 소유자를 확정합니다. 근거가 없거나 서로 충돌하면 소유자는 미확정이며, 파일명·ID의 코드·다수결로 보완하지 않습니다.

상단 선언으로 소유자를 보완하면 `organization_identity_source=source_declared_owner`와 `source_declared_owner`의 상태·이름·코드·근거 셀·사유를 제출본 및 `trial.submission_owner`에 보존합니다. 상세행의 조직코드와 값은 수정하지 않으며, 소유자와 다른 행 조직에 대한 후속 조립기의 진단 정책도 그대로 적용합니다.

정규금액이 미확정인 경우에는 원문값과 수식 정보도 비교합니다. 서로 다른 잘못된 숫자나 캐시 없는 수식이 같은 null 정규값으로 표시되었다는 이유만으로 동일 전달로 묶지 않습니다. 기술 조립을 위한 빈 월별 슬롯은 같은 원본에서 실제 항목·계정·거래 설명이 확인된 행에만 추가하며, 오류 자리표시만 있는 행은 별도 상세를 만들지 않습니다.

## 숫자 문자열의 원본 서식 근거

`_normalization_locale`은 명시 KRW 금액 단위와 원본 문자열·서식이 함께 뒷받침하는 경우에만 구분자를 확인합니다. `inspect_number_format`으로 각 서식 구간의 표시 배율·조건·백분율·날짜 여부를 먼저 확인하고, 회계 여백 제어인 `_문자`와 `*문자`만 제거합니다. 남은 양수 서식이 정확히 `#,##0` 또는 `#,##0.0`, `#,##0.00`처럼 점 뒤 0이 하나 이상인 형태여야 합니다. 문자열에도 정확한 3자리 쉼표 그룹이 있어야 하며, 앞 부호·괄호 음수와 그룹 뒤 점 이하 소수를 허용합니다. 이 경우에만 기존 `normalize_number`에 `ko_KR`을 전달하고 원문 소수 정밀도·부호·명시 단위 변환을 유지합니다. 표시 소수 자릿수에 맞춰 값을 반올림하지 않습니다.

표시 배율을 뜻하는 뒤쪽 쉼표, 조건부 서식, 백분율·날짜 서식, 따옴표 또는 이스케이프로 표시한 숫자 리터럴에는 이 로케일 보완을 적용하지 않습니다. 그룹 없는 단일 점의 의미가 모호한 문자열, 유럽식 구분자 서식, 단위 부재, 실제 숫자 셀도 대상이 아닙니다. 호출자가 locale을 명시했다면 그 값을 우선합니다. 원문·서식·단위·변환 규칙 ID는 출력에 남으며, 기존 규칙 ID의 `INTEGER_GROUPING`은 정수 부분의 쉼표 그룹 근거를 뜻합니다.

## 금액과 분리한 업무필드 검증

`business_validation.build_business_contracts`는 같은 원본의 `예산코드`·`예산명칭` 헤더가 있는 코드표와 실제 `SUMIFS` 수식의 전체 열 조건 범위·기준값을 읽습니다. `validate_business_row`는 그 계약으로 비용의 예산코드와 매출의 관리분류를 검사합니다. 관리분류는 실제 수식이 참조하는 기준 셀 또는 명시 문자열과만 대조하며 소분류·상세 ID·파일명으로 바꾸지 않습니다. 일부 행 범위, 외부 참조, 동적 기준식과 와일드카드는 전체 상세열의 허용 목록으로 확장하지 않습니다. 코드표가 없거나 집계 기준 전체를 직접 읽을 수 없으면 해당 필드는 `unverified`로 남습니다.

명시 ID의 `None`·`null`·`nan` 문자열은 관측값을 그대로 보존하면서 `detail_id.status=invalid`로 표시합니다. ID에서 조직·계정코드를 추론하지 않습니다. 미등록 계정·관리분류도 원문 필드와 읽힌 금액을 유지합니다. `value.status`, `normalized_value`, `item.code`, `item.detail_id`, 기존 `mapping.status`는 업무필드 검증 때문에 삭제하거나 변경하지 않습니다.

각 상세 레코드의 `business_validation`에는 적용한 검사 상태, 필드별 `status`·`observed_value`·출처와 문제 목록이 들어갑니다. 적용한 검사 실패는 `invalid`, 확인된 계약의 필수값 누락은 `unresolved`, 적용 가능한 검사가 전혀 없으면 `not_applicable`입니다. `valid`는 적용한 검사의 통과 상태이며, 함께 남긴 `unverified` 필드까지 유효하다고 주장하지 않습니다. 전체 코드표·기준값 목록을 매번 복제하지 않고 해당 입력 셀과 일치 근거, 또는 계약 헤더·범위·해시만 보존합니다.

`map_workbook`은 원본 계약을 한 번 만들고 동일 행의 결과를 캐시하여 월별 레코드에 연결합니다. 금액이 모두 빈 행도 재구성 단계에서 같은 `validate_business_row`를 호출할 수 있습니다. 후속 소비자는 금액 읽기 성공과 업무키 유효성을 구별하여 의미 완전성·합계 포함·동일 ID 묶음 여부를 결정해야 합니다. 원본 빈칸·실제 0·수식 캐시 누락 상태는 유지합니다.

## 집계와 미확정 상태

`mapping.status`는 다음 세 상태입니다. 제출 정보의 확인 상태는 별도로 유지합니다.

| 상태 | 의미 |
| --- | --- |
| `mapped` | 값 정규화와 조직 범위·항목·대상 기간·시나리오·필요 단위가 확인됨 |
| `partial` | 재무 값 영역이나 지표를 식별했지만 일부 의미나 정규화가 미확정 |
| `unmapped` | 재무 의미를 확인하지 못한 숫자·수식 후보 또는 비금액 참조 필드 |

원본의 값·수식 셀 수와 표준 재무/숫자·수식 후보 수는 같지 않을 수 있습니다. 제목·설명·문자열 코드 등은 원본 추출에 보존되며, 표준 숫자 목록에 들어가지 않을 수 있습니다. 원본 숫자·수식 후보는 표준 목록에서 제거하지 않습니다.

Contingency 또는 제외 영업이익을 확인할 근거가 없으면 해당 항목과 계산 관계를 미확정으로 남깁니다. 파서는 원본 지표와 수식을 연결하지만, 근거 없이 Contingency 제외 영업이익을 계산하지 않습니다. 숫자 저장 부호·캐시 누락·지원하지 않는 구조 등은 입력별로 진단하며 모든 입력의 의미 해석이 완료된 것으로 보고하지 않습니다.

## 제출 어댑터의 보고 항목과 원본 대조 근거

서비스 브리지 1.3은 표준 후보와 별도로 [제출 검증 어댑터](output-contract.md#서비스-제출-검증-어댑터)를 제공합니다. `submission_adapter.py`는 파일·DB 저장이나 승인 상태 변경을 하지 않으며, 모든 원본 기간을 보존합니다. 실제 업무 요청의 연도·유형 선택은 백엔드가 수행합니다.

- 매출은 상세 `관리분류`, 비용은 `실적집계기준`을 보고 말단에 연결합니다. 직접 SUMIFS의 합산 열, 같은 상세 시트의 조직명/분류 두 조건, 보고 셀의 기간, 조직표로 확인한 단일 소유 조직과 보고 계층의 말단명을 모두 확인합니다. 팀·과제·계정은 원본 행의 차원이며 이 양식의 보고 SUMIFS 조건으로 추가하지 않습니다.
- 비용 수식의 criterion이 **동일 보고 시트 E:E 전체 열**인 경우에만 현재 수식 행의 E셀을 기준값으로 읽습니다. 이는 현재 양식의 implicit intersection 패턴에 한정하며, 다른 열·다른 시트·동적 범위·범용 Excel 수식 평가를 지원한다는 뜻이 아닙니다. 원문 수식을 변경하지 않습니다.
- 단일 SUMIFS와 양수 숫자의 곱셈/나눗셈만 허용합니다. 추가 연산·함수·와일드카드·미확정 기간·단위는 추정하지 않습니다. 동일 계정 코드라도 관리분류가 다르면 서로 다른 보고 항목입니다. 동일 분류가 여러 경로에 대응하면 유일 매핑으로 확정하지 않습니다.
- 보고 캐시의 원 환산은 상세의 명시 단위와 수식 배율로 증명합니다. 보고 시트 자체의 단위가 없더라도 이 두 근거로 알려진 표시 단위를 확인할 수 있습니다. 반대되는 명시 단위가 있으면 연결을 거부합니다. 기존 표준 후보의 원문·정규화 값은 변경하지 않습니다.
- 매출/비용 총계는 같은 월 열의 SUM/더하기 참조가 모두 확인된 말단으로 끝나고 말단 중복·누락이 없을 때만 인정합니다. 같은 행의 유효 가로 공유 범위 안에 있는 상대참조 합계만 해석하며, 공유 수식의 원문/캐시는 그대로입니다. OP는 확인된 매출 총계 셀에서 비용 총계 셀을 한 번 빼는 직접 식만 인정합니다. 저장 캐시는 실행·재계산하지 않습니다.
- 활성 상세의 알려진 모든 월 열에 슬롯을 만들고 원본에 없는 셀, 저장된 빈 셀, 실제 0, 캐시 없는/오류 수식을 구분합니다. 확인되지 않은 월 헤더를 만들어 넣거나 빈 금액을 0으로 채우지 않습니다. 상세 ID·개정을 삭제·선택·합치지 않습니다.

`test_submission_adapter.py`의 메모리 회귀는 동일계정의 서로 다른 보고 분류, 비용 E:E, 원 환산, 월12개·0/빈칸/오류, 헤더 누락, 미등록 분류, 공유 총계, 허용하지 않은 추가 연산, OP 부호, 미사용 행 제외와 활성 조직 오류, 기존 후보 불변을 검사합니다.
